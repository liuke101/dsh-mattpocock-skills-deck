你要帮用户把 Forgejo 配好。用户可能从没用过 Forgejo，也可能从没装过命令行工具 `fj`。按下面的顺序走，每一步先说清「为什么做这一步」和「怎么算做完了」。

**任何 Forgejo 细节以实例页面与上游仓库为准，不要凭记忆答。** `fj` 的说明在 https://codeberg.org/forgejo-contrib/forgejo-cli ，用户自己那台实例的地址、版本与令牌页面只有他知道。

## 一、顺序

1. **先探，再装**。跑 `fj version` 和 `git --version`。有版本号就跳过安装，没有就照上游仓库的安装页装。
   判据：`fj version` 打出具体版本号。
2. **登录。** 先跑 `fj auth login`。它会在浏览器里打开授权页，请用户在页面上完成授权。
   如果这条走不通（比如没有浏览器、实例的授权页打不开），改走令牌：
   - 让用户在实例的「设置 → 应用」里新建一枚访问令牌，把 issue 与 repository 两类的读写范围勾上，其余按最小权限不勾；
   - 让用户把令牌存成一行文本文件，然后运行 `fj auth add-token -H <实例地址> < <令牌文件>`，让令牌从标准输入进去；
   - 喂完立刻删掉那个文件。**不要把令牌写在命令行参数里**，那会原样留在会话记录与进程参数中。
   判据：`fj auth list` 的名单里有这台实例。
3. **准备一个仓库。** 用户已有仓库时，确认本地 git remote 指向它：`git remote get-url origin` 应形如 `https://<实例地址>/<owner>/<name>.git`。没有仓库时，用 `fj repo create <owner>/<name> --private` 建一个，再让本地仓库把 remote 指过去并推送。
   判据：`fj -H <实例地址> repo view <owner>/<name>` 能读回仓库信息。
4. **收尾。** 把「实例地址、仓库的 owner/name」记下来，后面的活都要用这两个值。请用户回到 DSH 点「重查」。

## 二、容易踩的坑

1. **实例地址不能省。** Forgejo 是自建软件，没有唯一的默认域名。所有命令都显式带 `-H <实例地址>`；只写 `owner/name` 不足以定位仓库，同一个名字可以同时存在于好几台实例上。
2. **一个工作区有多个远端时，`fj` 会按远端名字母序取第一个。** 这就是本插件总用 `-r` 或 `-R` 显式选仓库的原因。用户手工跑命令时也一样，别让它自己猜。
3. **装完别急着信「能找到 fj」。** 宿主程序是在启动那一刻读 PATH 的，刚装好的 `fj`，当前开着的宿主仍然找不到。判据：宿主说找不到时，先用绝对路径跑一次 `fj version` 证明装好了，再让用户重启宿主。
4. **登录凭证由 `fj` 自己保管。** 不要去读它的凭证文件，也不要把里面的内容贴进对话；令牌一旦进了聊天记录就算泄漏，只能请用户去实例上撤销那一枚再重建。
5. **`fj` 的失败经常仍然返回退出码 0。** 它把错误打在文本里。判断「这一趟成没成」要看输出原文，不要只看退出码。
6. **界面语言会影响解析。** 本插件按英文输出解析 `fj` 的文本；用户把 `fj` 或终端切到别的语言后，读取会如实报「认不出」，不会猜一个错值。遇到这种情况先切回英文再重试。

## 三、我们这台机器上的一次实况（2026-11-05，可能过时，先探再信）

- `fj` 版本 0.7.0（forgejo-cli）；对端实例是 Forgejo 17.0.1。
- 登录走的是浏览器授权页；登录后 `fj auth list` 只打印实例地址，不打印账号。
- 用来验证的沙箱仓库是那台实例上的一个私有仓库；`fj repo view <owner/name>` 能读回名称与默认分支。
- 那一次踩到的正是上面第二节的第 1、2、5 条。
